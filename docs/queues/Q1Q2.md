## Q1 — restore checks and Phase 1 (target: Gate 1)

and `~/runs/golden_v2` (`cat … > /dev/null`) before any timed or heavy job. Then capture XLA greedy on the 20 day-1
prompts and compare with `~/runs/val/expected_p*.pt`. **Must be bit-identical.** If not, stop, document the
difference (driver/runtime version, NEFF hash) and fix the environment before any comparison.

**T2 Freeze the validator.** Turn the existing tools (`capture_tf.py`, `census.py`, `router_census.py`,
`compare_golden.py`, …) into one entry point `tools/validator/validate.py`: build dir → teacher-forced capture over
the corpus → one JSON with every spec row and pass/fail:

| Row | Metric | Gate |
|---|---|---|
| Op boundary, per layer | rel-L2 vs golden at attention out, MoE out, residual; ρ vs XLA | median ρ ≤ 1.25 per boundary, no layer > 2 |
| Router | top-8 set vs golden, tie-tolerant flip rate | ≤ XLA's + 0.5 pp |
| Logits, teacher-forced | mean KL(golden‖cand); top-1 | mean KL ≤ 1.25 × XLA's |
| Worst position | max KL; count where cand KL > 0.2 and XLA KL < 0.01 | count = 0 |
| Model quality | perplexity on a fixed natural-text set | within 0.5% of XLA's |
| Run-to-run | two identical captures | bit-identical or documented |

Write the thresholds to `results/phase1/spec.json`. Freeze: record SHA-256 of the validator, `spec.json`, the corpus
and the golden files in `results/phase1/FROZEN.md` and in every ledger entry; `chmod a-w` them; add a
`PreToolUse` hook that blocks Edit/Write/Bash touching those paths (time-box the hook to 1 h; if it fails, keep
chmod + hash checks and note it).

**T3 Corpus.** Keep the 24 existing prompts and add 40: prompt lengths ~8–700 tokens, 64–128 generated tokens,
total ≤ 768; mixed domains (prose, code, math, dialogue, lists, a little non-English). Perplexity set: 16 passages
× 512 tokens of public-domain or openly licensed text (e.g. wikitext-2-raw test). Fixed seeds, hashed. XLA greedy

**T4 XLA error budget.** Per-layer capture at every decode bucket (the `TensorRegistry.clear()` patch from Day 3b)
